# TwoDrive Office AutoSave 0.2.2 (Preview)

Large presentations could remain marked as modified after a successful local
autosave: the native PPTX exporter generates a new modification timestamp, and
the save acknowledgement mistook that clock change for another edit. Confirmation
now ignores only that timestamp in a validated PPTY v1 Core record. Slide content,
media references, other properties, newer edits and unknown layouts keep their
existing protections.

The 0.2.1 duplicate-write checks remain in place. No TwoDrive code, settings or
upload protocol changed. This preview still exports complete local files; it
does not implement Microsoft Office differential cloud synchronization.

Validation: 31 Python and 21 Node tests passed. Isolated ONLYOFFICE Desktop 10
saved a temporary copy of a 163-slide presentation while preserving all 293 media
resources. Delayed/lost acknowledgements, newer edits, idle file stability,
undo/redo, pause, native close protection and copy saving passed. The user also
reported successful edits after local installation; a read-only cache audit
found no new duplicate presentation generations from that editing session.

LibreOffice code is unchanged apart from the package version; no new LibreOffice
application test was run for this release. Desktop native adapter compatibility,
older SDK versions and real cloud round trips remain bounded by the
[verification record](../verification.md). Install while the editor is closed,
then open the document normally to load the update.
